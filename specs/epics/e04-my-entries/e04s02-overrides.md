# Story e04s02: Оверрайды серверных (b)

**type:** feat
**risk:** P1
**context:** domain
**Context:** Вариант (b): отдельная таблица
переопределений поверх серверного шаблона
(ключ пары + дата либо «все недели»,
изменённые поля). Серверный шаблон синк
заменяет нетронутым; конфликт — сравнением
хэша основы с новым серверным хэшем.
Схема e04s01 заложена без миграций под это.
Reason for Depth: отдельная таблица вместо
флага SERVER_EDITED — синку не решать судьбу
изменённой строки (§8 пп.1–2).

## Requirements

#### ADDED: Таблица оверрайдов
Ключ + scope даты/«все недели» + поля;
применение поверх SERVER при чтении.

#### ADDED: Детект конфликта
Хэш основы vs новый серверный хэш;
конфликт виден, молчаливой потери нет.

## Steps

1. Таблица + применение при чтении
→ verify: `./gradlew :app:testDebugUnitTest`
2. Конфликт по хэшу + UI-маркер
→ verify: `./gradlew :app:testDebugUnitTest`

## Verification Script

1. Переопределить аудиторию, прогнать синк
с тем же шаблоном — оверрайд жив.
2. Синк с изменённым шаблоном — конфликт виден.
